# Daily audit

`audit/daily.mjs` reads 1 day of the team's work and writes 1 short report with at most 5 proposals, each backed by facts. It is a script, not a drop-in: it adds nothing to the running server, and it needs no install, no module switch and no restart. The design, with every check and threshold, is [docs/plans/daily-audit.md](../plans/daily-audit.md).

```sh
npm run audit                                   # the day's report, in Odrade's reports folder
node audit/daily.mjs --no-llm --out-dir /tmp/audit-dry-run/$(date +%F)-daily-audit
```

- **It reads only.** Pocket's database opens with `readOnly: true`. `gh` gets only `gh api` GET requests, GraphQL queries (a `mutation` is refused) and `gh search prs`, at most 40 calls a run. Q1's blocking points use the last of them, with no compare call: at most 8 GraphQL queries of 40 PRs each (state and files, newest first), then at most 4 GraphQL blob queries of at most 150 object lookups each (each candidate file of the PR at the reviewed head and at the final head, newest first); the rest stay pending for the next run. A final result is kept in `findings.json`, and a later run reads it there and calls GitHub for it no more. `git` gets only `log`, `status` and `show`.
- **It writes 2 files:** `README.md` and `findings.json` in `$ODRADE_DIR/reports/YYYY-MM-DD-daily-audit/` (default `~/agents/odrade` when that folder exists, else `~/projects/odrade`), or in `--out-dir`. Other files in that folder stay as they are. Earlier days come from the sibling `*-daily-audit/findings.json` files, for "new, repeating, gone".
- **The checks come first.** `audit/checks.mjs` has 1 function for each check of the design (A1 to J1, P1, R1 and Q1). I3 reads each agent's home folder (`~/agents/<id>/`): a home with uncommitted files and a last commit more than 24 h old is 1 low finding. A check whose source fails is listed under "Skipped checks"; the run goes on. Q1 records the PRs that each run sees decided (merged, or closed unmerged) in `metrics.Q1.day`, sums the last 30 daily records, and gives "decided acceptance" ((merged − reverted) / decided) per repository and per agent; a low rate with enough data is 1 medium finding. Beside it, with no GitHub call, Q1 counts review rounds per desk thread (cross-review spawns and sends to them, 30 days, median and P90), night-shift goals stopped by the same check failure 3 times in a row, and CI reruns per repository from the newest `*-flaky-scan/scan.json`. Each such stop lists its failing jobs (`stopChecks`, or the job names of the failure fingerprint for an older goal) and the keys of the flaky-test scans of the last 30 days that match them, by repository and job name or by job id (`metrics.Q1.stops.goals[].checks`, `flakyKeys`, `flaky`). `flaky` is `false` only when a scan read the repository of every failing job with no error; else, with no match, it is `null` (unknown); a high or rising round median and 2 such stops of 1 repository in 7 days are medium findings. Q1 also measures 2 things from the session records, with no finding and no threshold: `prRounds`, the cross-review rounds of each PR (a round goes to the first PR of a desk owner that its message names, else to its `PR #N` in the desk thread's repository; a send with no PR takes the PR of the call before it; all earlier calls are read, with no lower time limit, so a spawn of any age still sets the round and the PR of a send or an answer in the window), with the mean, median, P90, the PRs with 3 or more rounds and the rounds with no PR; and `blockers`, each blocking point of a reviewer's answer (its PR, the reviewed head, the item label), with the PR's state and its guard: whether a test file or an `AGENTS.md` file of the PR's own diff is new or changed at the final head against the reviewed head (`test`, `agentsRule`; a deleted file does not count), and how many non-empty lines of `.memory/corrections.jsonl` are at the final head and not at the reviewed head (`corrections`, and `namesPr` when such a line names the PR); `guarded` needs both, and `rate` is guarded points over evaluated points. A PR whose answer has an error on its alias, or no whole file list, stays pending, never final. `blockers.guards` says how the run's guard read went: each kind of failed or partial GitHub answer once in `errors` (no GitHub text: for example "PR query returned no data" or "blob query missed a key"), the calls, and `pending`, every distinct `ref@head` with no final result yet, whatever deferred it (the PR limit, the cap, the query limit, a failed answer, an open PR); when the read fails or GitHub is off, it is `available: false` with the reason, and the points still show. Only refs, numbers, SHAs, item labels and booleans are kept, no answer text.
- **1 model call, with its limits in code** (`audit/llm.mjs`): `deepseek/deepseek-flash` through Pi's model runtime and Pi's stored sign-in; at most 30,000 input tokens, 2,000 output tokens and $0.50 a day; no call after 2 days over $0.50. The model sees only finding texts, metrics and, for up to 10 pairs, 2 report texts of at most 1,500 characters. Code checks its answer (at most 5 proposals, cited ids that exist, numbers from the cited findings). An answer that fails, or `--no-llm`, gives the plain ranked list.
- **No secrets.** A line that matches the redaction filter is dropped, not masked; a quote is at most 80 characters; report texts never go into the report or the JSON.
- **Options:** `--hours N` (default 24), `--date YYYY-MM-DD` (the label and the folder name; default today in America/New_York), `--out-dir DIR`, `--no-llm`, `--no-github`, `--json`. Environment: `PI_POCKET_DIR`, `ODRADE_DIR`, `TEAM_HOMES_DIR` (default `~/agents`; a missing folder reads as no homes).
- **Tests:** `audit/*.test.ts`, on invented fixtures (a temporary SQLite file, a fake `gh` and `git`, a fake model). They never read Brian's data or call a model.

Brian runs it each day at 06:30 America/New_York with a Pocket schedule in a "Daily audit" session; Odrade reads the report for the 07:30 brief.
