# Daily audit

`audit/daily.mjs` reads 1 day of the team's work and writes 1 short report with at most 5 proposals, each backed by facts. It is a script, not a drop-in: it adds nothing to the running server, and it needs no install, no module switch and no restart. The design, with every check and threshold, is [docs/plans/daily-audit.md](../plans/daily-audit.md).

```sh
npm run audit                                   # the day's report, in Odrade's reports folder
node audit/daily.mjs --no-llm --out-dir /tmp/audit-dry-run/$(date +%F)-daily-audit
```

- **It reads only.** Pocket's database opens with `readOnly: true`. `gh` gets only `gh api` GET requests, GraphQL queries (a `mutation` is refused) and `gh search prs`, at most 40 calls a run. Q1's blocking points use the last of them, with no compare call: at most 8 GraphQL queries of 40 PRs each (state and files, newest first), then at most 4 GraphQL blob queries of at most 150 object lookups each (each candidate file of the PR at the reviewed head and at the final head, newest first); the rest stay pending for the next run. A final result is kept in `findings.json`, and a later run reads it there and calls GitHub for it no more. `git` gets only `log`, `status` and `show`.
- **It writes 2 files:** `README.md` and `findings.json` in `$ODRADE_DIR/reports/YYYY-MM-DD-daily-audit/` (default `~/agents/odrade` when that folder exists, else `~/projects/odrade`), or in `--out-dir`. Other files in that folder stay as they are. Earlier days come from the sibling `*-daily-audit/findings.json` files, for "new, repeating, gone".
- **The checks come first.** `audit/checks.mjs` has 1 function for each check of the design (A1 to J1, P1, R1, Q1 and R2). I3 reads each agent's home folder (`~/agents/<id>/`): a home with uncommitted files and a last commit more than 24 h old is 1 low finding. A check whose source fails is listed under "Skipped checks"; the run goes on. Q1 records the PRs that each run sees decided (merged, or closed unmerged) in `metrics.Q1.day`, sums the last 30 daily records, and gives "decided acceptance" ((merged − reverted) / decided) per repository and per agent; a low rate with enough data is 1 medium finding. Beside it, with no GitHub call, Q1 counts review rounds per PR (30 days, median and P90): a round is 1 reviewed head of 1 PR, as `prRounds` below says. Each PR row has its own repository (never the repository of the thread), its agent (`agents[0]` of a desk thread that holds the PR, else the agent of the desk thread of the session of its latest round, else `unattributed`), its desk threads (`threads`: the threads that hold it and the threads of the sessions that reviewed it) and its reviewed heads (`metrics.Q1.rounds.prs`). A round with no PR does not count there. Q1 also counts shift goals stopped by the same check failure 3 times in a row, and CI reruns per repository from the newest `*-flaky-scan/scan.json`. Each such stop lists its failing jobs (`stopChecks`, or the job names of the failure fingerprint for an older goal) and the keys of the flaky-test scans of the last 30 days that match them, by repository and job name or by job id (`metrics.Q1.stops.goals[].checks`, `flakyKeys`, `flaky`). `flaky` is `false` only when a scan read the repository of every failing job with no error; else, with no match, it is `null` (unknown); a high or rising round median and 2 such stops of 1 repository in 7 days are medium findings. Q1 also measures 2 things from the session records, with no finding and no threshold: `prRounds`, the cross-review rounds of each PR. A round call is a cross-review spawn, or a send to a name whose latest spawn in that session was one. A round call goes to the first PR of a desk owner that its message names, else to its `PR #N` in the desk thread's repository; a send with no PR takes the PR of the call before it. All earlier calls are read, with no lower time limit, so a spawn of any age still sets the round, the PR and the head of a send or an answer in the window. A round is 1 reviewed head of 1 PR: `rounds` counts the distinct reviewed heads of the PR. The head of a call is the first full 40-hex SHA that these rules find in its message: (1) within 30 characters after `new`, `current`, `updated` or `latest`, an optional `PR`, and `head`; (2) B of `from A to B`, `A..B` or `A...B`; (3) within 30 characters after a word `head` that does not come after `previous`, `prior`, `old`, `last`, `earlier`, `former`, `reviewed` or `base`; (4) B of the bare pair `A B`. A call with no head takes the head of the call before it to the same name in the same session, when that call has the same PR (a batch message with no SHA is not a new head). A call is superseded, and is no reviewed head, when the next call to the same name in the same session is a round for the same PR and no answer of that reviewer came from the call to the next call: the reviewer got both messages in 1 run (a SHA correction, or a note that the head moved). Without the answers source, no call is superseded, and each distinct head counts. All calls of 1 reviewer chain with no head are 1 round. `heads` counts the distinct known heads of the calls that are not superseded, and `calls` counts all round calls of the PR, the superseded ones too. The totals have the mean, median, P90 and the PRs with 3 or more rounds (all over the reviewed heads), the round calls with a PR (`calls`) and the round calls with no PR (`unattributed`). The head parse also gives the reviewed head of each blocking point below: a re-review message that names the old head first now gives the new head; and `blockers`, each blocking point of a reviewer's answer (its PR, the reviewed head, the item label), with the PR's state and its guard: whether a test file or an `AGENTS.md` file of the PR's own diff is new or changed at the final head against the reviewed head (`test`, `agentsRule`; a deleted file does not count), and its correction records: the non-empty lines of `.memory/corrections.jsonl` at the final head and not at the reviewed head (`correctionsLegacy`) plus the new record files under `.memory/corrections/` (`correctionsFiles`; a record moved from the old file after the reviewed head is not new, and a record file that the read-only `gh` refuses is listed in `correctionsSkipped` and not counted), summed in `corrections`, with `namesPr` when such a line or file names the PR); `guarded` needs both, and `rate` is guarded points over evaluated points. A PR whose answer has an error on its alias, or no whole file list, stays pending, never final. `blockers.guards` says how the run's guard read went: each kind of failed or partial GitHub answer once in `errors` (no GitHub text: for example "PR query returned no data" or "blob query missed a key"), the calls, and `pending`, every distinct `ref@head` with no final result yet, whatever deferred it (the PR limit, the cap, the query limit, a failed answer, an open PR); when the read fails or GitHub is off, it is `available: false` with the reason, and the points still show. Only refs, numbers, SHAs, item labels and booleans are kept, no answer text.
- **1 model call, with its limits in code** (`audit/llm.mjs`): `deepseek/deepseek-flash` through Pi's model runtime and Pi's stored sign-in; at most 30,000 input tokens, 2,000 output tokens and $0.50 a day; no call after 2 days over $0.50. The model sees only finding texts, metrics and, for up to 10 pairs, 2 report texts of at most 1,500 characters. Code checks its answer (at most 5 proposals, cited ids that exist, numbers from the cited findings). An answer that fails, or `--no-llm`, gives the plain ranked list.
- **R2: routed threads end to end.** R2 runs after Q1 and reads its result. It takes every desk thread with a `route` (any delegation, not only shifts) and groups the threads by the arm they were assigned (intent to treat), not by the model that ran: tier rule, predicted tier, arm and assigned worker (`route.tierRule`, `route.tier`, `route.arm`, and `route.assigned`, else `route.worker`; `-` when absent). Its sources: the routed sessions' cost rows and spawn calls with no time limit (`routeCosts`, `routeSpawns`, which now keep each spawn's `thinking`), Q1's `prRounds` and `blockers`, and `parentEdits` (`loadParentEdits`: per routed session, the first subagent answer, the count of `edit` and `write` calls after it, and `editTimes`, the times of all its `edit` and `write` calls; no path or text is kept). A thread is `accepted` when it closed as done (`completed`, `verified` or no outcome), was never reopened for rework (see below), every PR (not a `window` link) merged, and no revert of any of its PRs came within 14 days of the thread's LAST merge (a revert at a time not known counts too); it is `pending` until 14 days after the last merge, or after the close when it has no PR. A revert is Q1's revert detection on the stored records, and also an explicit `Reverts owner/name#N` of a merged revert PR whose target has no record of its own (the desk link says it merged); a title revert still needs the target's record, for its title. Q1's own numbers do not use this addition. Dropped, failed, `abandoned`, `frozen`, reopened for rework, a PR closed unmerged, or a revert in the 14 days is `notAccepted`. `notAcceptedWhy` (`{ dropped, closedPr, reverted, reopened }`) counts each such thread in 1 reason only, the first that R2 finds, in this order: dropped (also failed, `abandoned`, `frozen`), reopened for rework, a PR closed unmerged, then a revert. R2 sorts each reopen event of the desk by its key and text. Only a rework reopening (`R2_REWORK_KINDS`) makes a thread `notAccepted`: `checks` (text `reopened: <ref> is conflicting` or `reopened: <ref> is failing`), `work` (`reopened: new work in its session`, or `reopened: work in its folder after a supervisor message`) and `busy` (`reopened: its session is busy`: the session ran again after the close, and not for a supervisor message, which gives a quiet wake and keeps the thread closed). The other kinds are bookkeeping, not rework: `watch` (key `reopened:watch:`, text `reopened: watch set by <actor>`, a watch that verifies the work), `attached` (`reopened: <ref> attached by <actor>`), `sweep` (`reopened: a PR it made is open`, the sweep found and attached a PR), `report` (`reopened: a report after a supervisor message`: a report alone is no new work; but the desk names the report before it looks at the folder, so a `report` reopening is `work` when the session worked after the close before it: an `edit` or `write` call of the session (`editTimes`), a worker spawn that is not a cross-review, or a `subagent` send to a worker (a send counts when the latest spawn of the same name in the session, before it, is no cross-review spawn; a send with no earlier spawn of its name does not count), in the interval from the latest close of the done thread before the reopen (an event key `closed:` from the sweep, or `watch:pass:` from a passed watch) to the reopen; with no such close event, no session, or no evidence, it stays `report`; without the `parentEdits` source the edits do not count, and without the `reviews` source the sends do not count), `ask` (key `reopened:reopen:`, a plan ask reopened; or key `ask:<id>:<time>` with the text `ask <id>[ from <name>] reopened the thread: …`, an ask that reopened the closed thread; an ordinary ask event is no reopening) and `other` (any other text: an unknown text is not rework). No desk event reopens a thread for a blocking review: a review that brings work back shows as new work in the session or as failing checks, so R2 has no review kind. `reopenedBy` counts the rework kinds of the `reopened` threads, and `reopenedNotRework` the other kinds of every thread of the row, whatever its outcome (in both, a thread counts each kind once); another close, or a PR whose state is not known (an open, missing or frozen link with no Q1 record), is `unknown`. A PR's state comes from the desk link, else from Q1's stored day records; its merge time from those records, else this run's GitHub read, else the thread's close (a late bound, counted in `closeAsMergeTime`). R2 makes no GitHub call of its own: it reads every complete Q1 day record of the earlier days (no 30-day limit) and today's. A worker spawn (not a cross-review; no model means the profile model) on another model than the assigned one, or on another thinking level than `route.assignedThinking` or the goal's `workerThinking`, is a deviation. Per row: the count, open, accepted, not accepted, pending and unknown threads, the accepted rate over decided threads (shown only at 10 decided or more), the cost per accepted thread (the cost of every decided thread over the accepted ones, so failures count in the cost), the median review rounds (the sum of Q1's `prRounds` rounds, the reviewed heads, over the thread's PRs; null without Q1, and a thread with no PR has no rounds and no blocking points, so it does not count in the median; Q1's `prRounds` and `blockers` cover the last 30 days only, so these are not lifetime totals, and a PR reviewed earlier shows 0 rounds), the blocking points, the hand-fix rate over the threads with a known edit row, the deviations, the workers and thinking levels that ran, and the eligible threads. `eligible` is the share of routed shifts that name no worker, have the Jev kind `implement`, `debug`, `refactor` or `write`, are on a bench repository (`R2_BENCH_REPOS`), and whose route says that no risk path is named (`features.riskPathNamed: false`). `null` (the router could not read a risk-path list) and a route with no `features` (an older route) are unknown: such a thread counts in `nightShifts`, not in `eligible`. R2 makes no finding; the report shows its first 10 rows as a table, then 1 line with `notAcceptedWhy` and `reopenedBy` of the totals when a thread is not accepted, and 1 line with `reopenedNotRework` when it has a count.
- **No secrets.** A line that matches the redaction filter is dropped, not masked; a quote is at most 80 characters; report texts never go into the report or the JSON.
- **Options:** `--hours N` (default 24), `--date YYYY-MM-DD` (the label and the folder name; default today in America/New_York), `--out-dir DIR`, `--no-llm`, `--no-github`, `--json`. Environment: `PI_POCKET_DIR`, `ODRADE_DIR`, `TEAM_HOMES_DIR` (default `~/agents`; a missing folder reads as no homes).
- **Tests:** `audit/*.test.ts`, on invented fixtures (a temporary SQLite file, a fake `gh` and `git`, a fake model). They never read Brian's data or call a model.

Brian runs it each day at 06:30 America/New_York with a Pocket schedule in a "Daily audit" session; Odrade reads the report for the 07:30 brief.
