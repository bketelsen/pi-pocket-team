# Replay bench

The replay bench replays merged tasks on candidate models, each attempt in a `bwrap` sandbox, to measure cost, tokens, wall time and quality. The contract is the T1064 plan ("Route workers by measured task complexity"), sections "Pre-registration", "Bench", "Scoring" (the result schema) and "Cost and budget".

Nothing here is a Pi Pocket module: `install.mjs` does not install it.

## Scripts

| Script                  | What it does                                                                                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bench/run.mjs`         | 1 attempt of 1 model on 1 manifest task: budget reserve, slots, auth pre-flight, scratch clone, setup, then Pi in the sandbox. Writes 1 result file. Idempotent.      |
| `bench/batch.mjs`       | Every (task, model) pair of a manifest as `run.mjs` children, `--parallel` at a time. Holds the halogen lease when halogen is in the batch. Prints a table per model. |
| `bench/load-test.mjs`   | Halogen only, under the lease: levels 1 to 4 of parallel attempts, then the halogen concurrency (highest level with no error and each attempt at 70% of level 1).     |
| `bench/report.mjs`      | A stage's summary per model: attempts, failures by kind, list cost, tokens, median and max wall time, and the total cost.                                             |
| `bench/budget.mjs`      | The budget guard: `set --budget <usd>`, `show`, `reap` (settles reservations of dead runners at their full cap).                                                      |
| `bench/harvest.mjs`     | Candidate tasks from the desk: 1 manifest per bench repository, validated in the sandbox. `--revalidate <file>` runs a file's commands again.                         |
| `bench/score.mjs`       | S0 to S3 of 1 result file: protocol, the repository check, the hidden tests, and the 2 judges. Adds the scores to the result file.                                    |
| `bench/calibration.mjs` | The judge calibration sets: 20 development pairs and 8 blind held-out diffs per owner, from the daily audit's blocking review points.                                 |
| `bench/judge-v1.md`     | The judge prompt: the rubric, the brief, S1, S2, the submitted diff and the reference diff ("1 accepted solution, not the only one").                                 |
| `bench/pilot.json`      | The pilot manifest: 3 pi-pocket-team tasks (small, medium, large), picked by hand.                                                                                    |
| `bench/models.json`     | The 10 candidate models; `priced: false` for a model with no list price; `peakUtc` for DeepSeek's peak hours.                                                         |
| `bench/header-v1.md`    | The bench header: the first part of every prompt, and `/agent/AGENTS.md` in the sandbox.                                                                              |
| `bench/hosts`           | The sandbox's `/etc/hosts`: GitHub's hosts go to 127.0.0.1.                                                                                                           |

Examples:

```sh
node bench/budget.mjs set --budget 3000
node bench/run.mjs --manifest bench/pilot.json --task pilot-small --model github-copilot/gpt-6-luna --stage pilot --dry-run
node bench/batch.mjs --manifest bench/pilot.json --stage pilot --models all --tasks all
node bench/load-test.mjs --manifest bench/pilot.json --task pilot-small
node bench/report.mjs --stage pilot
node bench/harvest.mjs --since 2026-09-01 --parallel 2
node bench/harvest.mjs --revalidate ~/agents/sheeana/bench/pi-pocket-team.json
node bench/score.mjs --result bench/results/stage1/<task>/<model-slug>.json
node bench/calibration.mjs
```

## Exit codes of `run.mjs`

| Code | Meaning                                                                                                                                                                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 0    | Attempt recorded (also a failed attempt, a limit, or a result that exists: then it prints `exists` and does nothing).                                                                                                                                                                      |
| 1    | Usage error: a bad argument, an unknown task or model, a model not in `bench/models.json`, halogen without the lease, `bwrap` missing, a limit of 0 for the limit that counts (`--cost-limit` of a priced model, `--token-limit` of an unpriced one), or the same attempt already running. |
| 2    | Budget refused, or a DeepSeek attempt in DeepSeek's peak hours. Nothing is spent.                                                                                                                                                                                                          |
| 3    | Harness failure after 3 tries (setup failed, auth pre-flight failed, or Pi ended before any assistant message). The result has `harness: true`.                                                                                                                                            |

`--dry-run` validates everything and prints the bwrap argv and the budget state; it reserves, clones and starts nothing, and needs no `bwrap`, data dir or auth file.

## Sandbox

Each try runs `bwrap --unshare-pid --unshare-ipc --die-with-parent --new-session --clearenv`, in its own process group. The network stays open (model providers, the halogen endpoint, module registries).

| In the sandbox                                                           | From the host                                                                                                                        | Mode       |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ---------- |
| `/work`                                                                  | the try's scratch clone (at the parent; no ref, tag, remote, reflog or merge)                                                        | read-write |
| `/session`                                                               | the try's `session/` folder                                                                                                          | read-write |
| `/agent`                                                                 | `<data>/agent/`, shared by all tries                                                                                                 | read-write |
| `/agent/AGENTS.md`                                                       | `bench/header-v1.md`                                                                                                                 | read-only  |
| `/agent/settings.json`                                                   | `<data>/agent-files/settings.json` (`{}`)                                                                                            | read-only  |
| `/agent/models.json`                                                     | `~/.pi/agent/models.json` (`--agent-src`)                                                                                            | read-only  |
| `/agent/auth.json`                                                       | `~/.pi/agent/auth.json` (`--agent-src`)                                                                                              | read-write |
| `/pocket`                                                                | the Pi Pocket checkout (`--pocket`)                                                                                                  | read-only  |
| `/usr`, `/etc/ssl`, `/etc/pki`, `/etc/nsswitch.conf`, `/etc/resolv.conf` | the host (`/bin`, `/lib` and the like are symlinks into `/usr`)                                                                      | read-only  |
| `/etc/hosts`                                                             | `bench/hosts`                                                                                                                        | read-only  |
| `/etc/passwd`, `/etc/group`                                              | `<data>/agent-files/passwd` and `group`: 1 user `bench` with the host's uid and gid, home `/home/bench` (`os.userInfo()` needs them) | read-only  |
| `/tools`                                                                 | `~/.local/share/mise/installs` (`--mise-installs`)                                                                                   | read-only  |
| `/cache`                                                                 | the try's `cache/` (`go`, `npm`, `pip`)                                                                                              | read-write |
| `/overlay`                                                               | S2 only: a staging folder of the reference's hidden-test files, written from the local checkout                                      | read-only  |
| `/trusted.git`                                                           | the submitted diff only: the git folder of a disposable clone of the local checkout at the parent                                    | read-write |
| `/tmp`, `/home/bench`                                                    | tmpfs                                                                                                                                | read-write |

Environment: `PI_CODING_AGENT_DIR=/agent`, `HOME=/home/bench`, `PATH` (node, then the newest Go and Python under `/tools`, then `/usr/bin:/bin`), `GOMODCACHE`, `npm_config_cache`, `PIP_CACHE_DIR`, `BENCH_TRY`. bwrap adds `PWD`. Nothing else: no `GH_TOKEN`, no `SSH_AUTH_SOCK`.

Before each try of an OAuth provider, the runner refreshes the token on the host (`pi auth print-bearer-token --min-expiry 60m`, output ignored), so the sandbox needs no refresh. It reads only the `type` field of the auth file.

## Limits and retries

- Per attempt: 45 minutes of Pi wall time; $8 of list cost for a priced model, 4,000,000 tokens for an unpriced one. The limits count over all tries of the attempt, and a limit is reached at its value (not only above it). The usage includes automatic compaction (`compaction_end` `result.usage`). At a limit: SIGTERM to the process group, SIGKILL after 10 s, `failure: "limit"`. A retry does not start when the attempt's allowance is used up: `failure: "limit"`.
- Budget: an attempt reserves its cap once (the cost limit for a priced model, $0 for an unpriced one), keeps it across its retries, and settles the sum of all its tries once at the end (the entry holds `tries`). A priced model always settles its real cost; an unpriced model settles $0 and keeps its tokens. Each try's usage reaches the settlement as soon as its Pi run ends; when the runner fails while a Pi run's usage is unknown, the attempt settles at its full cap (`usageUnknown: true`).
- A provider error (`stopReason: "error"` on the last assistant message): 1 retry on a fresh clone; then `failure: "provider"`.
- A harness failure: 2 repeats on a fresh clone, then `harness: true` and exit 3.
- A stream with no final event, or with an assistant message that did not end: `usage.partial: true`.
- `wallMs` in a result is the sum of the tries' Pi wall time (not clone or setup time).

## Data

The data dir is `$BENCH_DATA`, else `~/.local/share/pi-pocket-team/bench` (folders 0700, files 0600). It holds `spend.json` (the budget), `slots/`, `halogen.json`, `agent/`, `agent-files/` (`settings.json`, and the sandbox's `passwd` and `group`, written when missing or different) and `runs/<stage>/<task>/<model-slug>[--<run-id>]/try-<n>/` with `work/`, `session/`, `cache/`, `events.jsonl` and `stderr.log`. The harvester adds `manifests/`, `harvest-cache/` (validations, `gh` facts, command logs `<pr>.log`, and `revalidate/<task>.log`) and `harvest-work/` (scratch clones, removed after each validation); the scorer adds `diffs/`, `judges/<stage>/<task>/<attempt>/<judge>/try-<n>/` and `score/` (copies, removed after scoring; the log `score/<stage>/<task>/<attempt>.score.log` stays); the calibration builder writes `calibration/`. Every cleanup of a scratch tree or cache first adds the owner's write permission when `rm` meets a read-only folder (Go writes its module cache read-only); a cleanup that still fails is logged with its path and does not stop the work. A candidate whose validation throws is dropped with the reason, and the harvest goes on. Run folders are kept; a new run of the same attempt continues the try numbers. Result files go to `bench/results/` (ignored by git) or `--results`.

Attempt lock: `runs/<stage>/<task>/<model-slug>[--<run-id>].lock` (with the pid) is held from before the result-exists check until the result is written; a second runner of the same attempt exits 1. A lock of a dead pid is free. The take and the release both hold the short lock `runs/.locks.lock`.

Concurrency: at most 4 tries on the host and 2 per provider; halogen at most the `concurrency` of `halogen.json` (1 before the load test). `--max-provider` and `BENCH_MAX_PROVIDER` (load test only) change only halogen's cap. Halogen needs the lease: `~/.pi/agent/bin/lease take halogen T1064 "bench"` (`batch.mjs` and `load-test.mjs` take it themselves).

## Harvest

`node bench/harvest.mjs --since <date> [--until <date>] [--out <dir>] [--repo <owner/name>]... [--parallel <n>] [--fetch] [--bwrap <path>] [--pocket <dir>] [--db <file>] [--roster <dir>]` reads the desk from Pocket's database (`$PI_POCKET_DIR/pocket.sqlite`, else `~/.pi-pocket/pocket.sqlite`, read only) and writes 1 manifest per bench repository to `<out>/<github owner>/<repo>.json` (default `<data>/manifests`).

- Bench repositories and owners: `bench/lib/owners.mjs` (the plan's table). Checkouts come from the team roster (`~/.config/pi-pocket-team/agents/*.md`, `repositories:`; `PI_POCKET_TEAM_AGENTS` or `--roster` changes the folder).
- A candidate: a thread with exactly 1 PR, in a bench repository, named by no other thread, with a brief; GitHub (`gh pr view --json mergeCommit,mergedAt,files,additions,deletions,state,headRefOid`, read only) says MERGED, with `mergedAt` in the window (`--until` is inclusive); the merge commit is in the local checkout (no fetch without `--fetch`). Each other case is in the manifest's `dropped` with its reason.
- The brief: a night shift's goal (`objective`, a blank line, `Stop when: <stop>`; `briefSource: "night-shift"`), else the task of the thread's first message: the text after `Task from the source session:` and before `</linked-session-message>`, without the night-shift paragraph (`briefSource: "delegation"`).
- Size: additions + deletions; strata up to 50, 51 to 300, over 300 lines. Per stratum: night shifts first, then other delegations, each in a seeded order (mulberry32, seed 1064); validation runs in that order until the stratum holds 20 valid tasks. The candidates not validated are in `notValidated`.
- Validation, in the sandbox with no credential (no `/agent`): a scratch clone at the merge (setup, then the check, 10 minutes each, must pass); a scratch clone at the parent (the features of `model-router.ts`, the setup, the hidden tests). It is cached in `<data>/harvest-cache/<owner>/<repo>/<pr>.json` (by the validation version, now 2, the commits, the commands and the brief); an unexpected error (`validation error: …`) is never cached or reused. The log `<pr>.log` holds each command's stderr; when a setup, check or hidden-test command fails, the last 200 lines of its stdout follow it, after a header line that names the step (npm and the test reporters print their failures on stdout). `--revalidate` and the scorer's S1 and S2 log the same way.
- Proposed commands, from the files at the merge: setup `PI_POCKET_CHECKOUT=/pocket node link.mjs` (a `link.mjs` with a `link` script; the check gets the same prefix), else `npm ci`, else `go mod download`, else a venv in `/cache/venv` (Python). Check: Makefile `test`, else Makefile `verify`, else `npm test`, else `go test ./...`, else pytest.
- Hidden tests (S2): the PR's added or changed `*_test.go`, `*.test.ts`, `*.test.mjs`, `test_*.py`, and its files under `testdata/` or `fixtures/`. They run with a machine-readable reporter (Node's TAP, 1 run per file; `go test -json`; pytest's junit XML) at the merge, and at the parent with the files copied over it. A name is valid only when it fails by an assertion at the parent and passes at the merge; a file (Go: a package) that does not load or build at the parent is dropped. The unit of a name: a Node top-level test (Node 24 runs a subtest only when its top-level test matches the pattern, and then runs all its subtests), a Go top-level `Test` function, a pytest node id. `hiddenCommand` runs only the valid names; it must pass at the merge and fail at the parent, else the task has no S2.
- Manifest: `{ schema: 1, repo, checkout, generatedAt, since, until, tasks, dropped, notValidated, validation }`; each task has the schema v1 fields, with `owner: { keep: null, reason: "", scopeMatches: null, commandsConfirmed: null }` until its owner reviews it.
- `--revalidate <file>` (a reviewed copy too) runs each task's `setup`, `check` and `hiddenCommand` as written: setup and check at the merge must pass; the hidden command must pass at the merge and fail at the parent with the task's `hiddenTests` copied over it; and each named test must fail by an assertion at the parent and pass at the merge, by the harvest's reporters and rules (a non-zero exit is not enough: a test that does not load at the parent fails too). A failure names the test and the reason. The reporters go into the reviewed `hiddenCommand` itself, so its settings (an environment variable, `-tags`, a loader, a venv path) stay. A quote-aware tokenizer (single quotes, double quotes, backslash escapes) splits the command into `&&` segments of words, and each segment keeps every word as written; the runner is found by its words (environment assignments, then `go test`, `node ... --test`, `pytest`, or a `python` with `-m pytest`), not by text inside a quoted pattern. `go test` gets `-json`, `node --test` the TAP reporter (1 named file per run), pytest `--junitxml` in `/cache`. A segment with no such runner fails with "cannot add a reporter to the hidden command: <segment>"; `;`, `||`, `|`, a lone `&`, a newline, `<`, `>`, `(`, `)`, a backtick or `$(` fails with "the hidden command uses shell syntax that revalidation does not support: <what>". It writes the outcome into the file's `validation` (the tasks and `owner` stay as they are), prints 1 line per task, and exits 1 when a task with `owner.keep !== false` fails.

## Scoring

`node bench/score.mjs --result <file> [--manifest <file>] [--checkout <dir>] [--force]` scores 1 attempt. Without `--manifest`, the task is looked up in `bench/pilot.json` and `<data>/manifests/**`; it must be in exactly 1. The checkout is `--checkout`, else the manifest's `checkout`, else `~/projects/<name>` (the runner uses the same rule). The submitted tree (`workDir`) must be a folder; it needs no `.git` of its own. It adds these fields and keeps every other:

| Field                     | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `s0`                      | `{ protocol, leakTry }` from every try's `events.jsonl`, each try parsed on its own (call ids of 2 Pi runs can repeat): `protocol` when a `bash` command or a `read` path names `/agent/auth.json` (then `failure: "protocol"` when no other failure is set); `leakTry` when a command names the PR number with `pull`, the repository's GitHub URL, or its Go module path with `@`.                                                                                                                                                                                                                                                                                                                        |
| `s1`, `s1Detail`          | The manifest's `check` in a copy of `workDir`, in the sandbox (no credential, the try's `cache/` at `/cache`), 10 minutes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `s2`, `s2Detail`          | `hiddenCommand` in a second copy, after the `hiddenTests` files of the merge are copied over it inside the sandbox, from a staging folder bound read-only at `/overlay` (the copy may hold the worker's symbolic links; inside the sandbox they reach neither the host nor the submitted tree). Each staged file has its mode in the reference tree (`100755` is 0755, `100644` is 0644, `120000` a symbolic link), and the copy keeps it. Before the copy, each staged path's destination in the copy is removed (`rm -rf --`, 1 argument per path), so a folder of the worker's at a reference file's path does not stop S2; `null` when the task has none.                                               |
| `grades`, `judges`        | `[g1, g2]` of `openai/gpt-6.1-sol` and `github-copilot/claude-opus-5.5` (Claude Opus 5.5 runs on the Copilot route: the route `anthropic/claude-opus-5-5` returns HTTP 400 for the Pi CLI); `judges` holds each judge's grade, reasons, tries, cost and `pending`.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `diffCut`, `referenceCut` | The submitted (or reference) diff is over 60,000 characters: the judges get its `--stat` and its first 60,000 characters.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `judgePending`            | A judge gave no parsable answer in 3 tries, or the budget refused it: a later run judges only the judges with no grade. It is never a fail.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `diffFile`, `scoredAt`    | The submitted diff in `<data>/diffs/`, and the time of the score. In the sandbox with no credential, on a copy of the tree without its `.git` and without every `.git` below it (a nested repository or a submodule folder is diffed as its files, never as a gitlink): `git add -A`, then `git diff --cached --no-ext-diff --no-textconv --text <parent>`, with trusted git metadata only (`--git-dir` of a disposable clone of the local checkout at the parent, at `/trusted.git`; no system or global config; the attributes of the parent tree by `GIT_ATTR_SOURCE`, git 2.40 or later). The worker's git config, index and `.gitattributes` choose nothing. Host git runs only in the local checkout. |

A result with `harness: true` is not scored. A result with `failure` (limit, provider, protocol) gets S0 only. A scored result is not scored again without `--force`. Each judge runs the Pi CLI in the sandbox with `--no-tools --no-extensions --no-skills --no-mcp --no-context-files --no-prompt-templates --no-session`, the prompt as `@/work/judge-prompt.md` (a file, not an argument) followed by a short message that asks for 1 JSON object, after the OAuth pre-flight (`--min-expiry 30m`, which covers the judge's 20-minute wall limit; an OpenAI OAuth token never has the runner's 60 minutes left). An answer counts when it holds exactly 1 valid `{ grade, reasons }` object: the whole text, else its 1 fenced code block, else its 1 top-level `{...}` object. Each try reserves $1 under the budget guard and settles its real list cost; the judge cost is never part of `usage`. Exit codes: 0 scored (a judge may be pending), 1 usage error, 2 budget refused (the judges not run stay pending), 3 scoring error after S0: the result is saved with every score so far, `judgePending: true` and `scoreError` (the first line of the error); run again, and a run that succeeds removes `scoreError`.

## Calibration

`node bench/calibration.mjs [--findings <file>]... [--out <dir>]` reads the blocking review points (`metrics.Q1.blockers.points`) of every `~/agents/odrade/reports/*-daily-audit/findings.json` (1 per `ref@head`, merged PRs only), reads each PR (`gh pr view --json headRefOid,baseRefOid,mergeCommit,title,body,state`) and its diffs from GitHub's compare API (`base...head`, the same base for both diffs of a PR), all read only, and writes to `<data>/calibration`:

- `held-out/<owner>.json`: 8 diffs of the owner's bench repositories from 8 PRs, 4 at a Not-ready head and 4 at the final merged head, in a blind order; items `{ id, repo, pr, brief, diff, diffCut, label: null }`.
- `held-out-key.json`: `id` -> `{ label: "notReady" | "merged", head, repo, pr }`.
- `dev.json`: 20 pairs from the other PRs: `{ id, repo, pr, brief, base, notReadyHead, mergedHead, notReadyDiff, mergedDiff, notReadyCut, mergedCut }`.

Every choice is seeded (mulberry32, seed 1064). With fewer PRs it writes fewer items and prints a warning.

## Tests

`bench/*.test.mjs` use a fake `pi` (`bench/fixtures/fake-pi.cjs`; a judge reads its scenario from its `@file`), temp data and lease dirs, and a fixture git repository. The harvester, scorer and calibration tests add a Node-only fixture repository with a merged PR, a fixture Pocket database and a fake `gh` (`bench/fixtures/harvest.mjs`); Go and pytest output is canned. Most run behind a fake `bwrap` (`bench/fixtures/fake-bwrap.mjs`, no isolation); `bench/sandbox.test.mjs` uses the real `bwrap` and skips where it cannot run. No test calls a model.
